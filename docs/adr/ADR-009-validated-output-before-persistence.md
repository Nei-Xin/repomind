# ADR-009: Model output must pass structured validation before persistence

Status: accepted

## Context

LLM output can be malformed, hallucinated, or adversarial (prompt injection through diffs and logs). Anything written to the database becomes long-term "truth" for future sessions.

## Decision

Nothing generated by a model may reach the database without passing schema validation (Zod) plus deterministic checks: evidence IDs must come from the input set, and every candidate must bind to at least one evidence row. Validation failure aborts the write; it never produces partial memories. The current release uses deterministic extraction only, so this gate currently applies to external inputs (commit payloads, datasets) and becomes mandatory for the future LLM extractor.

## Consequences

- CLI/MCP inputs are already schema-validated (`commit --input`, eval datasets, tool schemas).
- The LLM extractor (M4) must be implemented behind this gate and be fully testable with a mock runner.
- Repository text (diffs, logs, tasks) is treated as untrusted data, never as instructions.
