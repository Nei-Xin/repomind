# Solution 摘要整理

新生成的 solution 可对明确的交接布局做保守整理：具体决策和约束排在会话操作记录
之前，删除独立的“Completed the coordination-only change.”等无实质信息的完成句。
标题取整理后正文中首个符合句式要求的完整句，跳过已识别的泛化完成句及段落标题，
最长 160 字符，过长时使用完整回退标题，不截断成半句话，也不跳到下一句。
警告或条件标题后无法安全提取完整句时使用回退标题。文件关联仍来自本次实际变更，
不从摘要提到的路径猜测关联。当前规则不保证能从任意自然语言摘要中提取具体决策。

目前识别独立完成句、明确的操作记录，以及有限的交接段落引导语，例如
`Preserved decision for the next maintainer:`、`Preserved for the next maintainer:`、
`Durable … constraints preserved for the next maintainer:`、`交接决策：`和`交接约束：`。
也支持带领域词的 `Completed the coordination-only … closeout.` 完成句，以及
`Preserved the durable contract for the follow-up:`、
`Durable contract for the follow-up:` 和其 `implementation` 变体。
支持实测的加粗交接标题、列表内的交接项及其缩进子项，也允许省略开头完成句。
具体主题的标题会保留，避免失去适用范围；交接之后的整个段落保持连续，包含后续
限制和未完成事项。只有前文逐行符合操作记录形式时，才将其移到交接内容之后。
前面有警告、自由文本解释、代码围栏、引用块、多个交接段落或不支持的布局时，
原文保持不变。这不是通用语义摘要器。

只调整顺序与固定套话，不删除文件、命令、验证陈述、失败方案、适用条件或剩余工作，
也不将任务要求推断为已实现的事实。摘要中声称测试通过不改变现有验证来源规则。
原始摘要仍完整保存在 `agent_summary` Evidence，solution 继续关联原证据；幂等提交
继续按原始请求校验。现有记忆不批量迁移或重写。

Host 和交互式 L1 注入在正文已以完全相同的标题开头时省略额外标题行；只命中子串
或标题带有独立限制时不会省略。正文和 warning 保持引用格式，召回 ID、字符数和
哈希仍按最终渲染内容记录。

用两份真实摘要在独立临时仓库中回放后，决策、精确字符串、数值范围、验证陈述和
未完成事项全部保留，原始 Evidence 与输入逐字一致。仅比较相同 L1 输入、空 L2/L3
的最终渲染字符，digest 从 955 降为 824，gateway 从 1208 降为 1188。

这里的绝对字符数不应直接与其完整 prompt 字符数混算。

18 个真实阶段均通过公开和隐藏验证；6 对均完整召回对应 solution，原始摘要

原始 token/工具事件与报告一致，无遗留 open session 或 running host。

正文整理触发 **0/6**，存储标题变化 **0/6**；真实交接使用了不同引导语、嵌套
列表、Markdown 标题或不支持的操作记录形式。四份 solution 仍以泛化完成句为
标题，另两份仍以删除笔记的记录为标题，因此尚未验证正文重排或实质标题的收益。

实际生效的是 5 对中的重复标题行省略，每次减少 42–49 个注入字符。仅看这 5 对，

两个小型任务不足以证明稳定效率提升，字符减少也不能换算为固定 token 节省比例。

此次真实对照暴露的格式覆盖和标题问题，由下面的后续回归修复处理。
