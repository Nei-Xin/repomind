# 当前项目审查与修复记录（2026-10-02）

审查基线为 `feat/memory-quality-rules` 分支的 `176e76a`，包含原有 Claude 的记忆质量规则改动及后续修复。当前源码版本为 `1.0.0-rc.3`。改动按结构化脱敏、数据库并发、记忆质量与审计、OpenCode 收尾、文档与验收记录分组提交。本次仅完成本地验收与 Git 提交，不包含发布或服务升级。

当前本机验证全部通过，但这不等于已验证真实模型收益或所有平台的发布质量。下一阶段更值得投入的是实际使用效果与扩展性，而非继续增加记忆种类。

## 本次修复

| 范围 | 修复后的行为 |
| --- | --- |
| solution 门槛 | 交互任务仅在修改仓库文件或通过可信测试时生成 solution；只读回答保留为 Evidence/L0。调用方自报通过不能冒充观察到的测试。 |
| 命令复用 | 相同规范化测试命令再次通过时更新既有记忆、证据和验证时间；文件关联与 FTS 在同一事务更新。 |
| partial 判定 | 探索命令失败不降级任务；逐项跟踪测试、构建、类型检查和 lint，只有可信的后续通过才能清除对应未完成验证。 |
| Shell 边界 | 保留目录、参数、引号内空白和重定向字符；不把 `npm test \|\| true`、管道或后台命令的状态当作测试通过证明。不同目录的测试不能互相清除失败。 |
| 标题 | 跳过 Markdown 标题、代码围栏及悬空的“运行：”引导语；优先使用完整实质句，过长时使用完整回退标题。 |
| 召回审计 | 从最终渲染文本生成审计，只记录截断后保留的记忆，保存文本、哈希、ID、版本、字符数和截断状态；后续召回也单独记录。 |
| 生命周期 | 创建任务、Session 和绑定活动保持原子性；重放已完成的开始事件不会留下孤立 Session 或覆盖其他活动任务。 |
| OpenCode 收尾 | 兼容两种 idle 通知，正常 dispose 时等待钩子及 Bridge 队列，重复通知只提交一次；一次性 `opencode run` 在退出时完成任务收尾。 |
| 脱敏 | 按 password、API key、authorization 等字段名递归遮盖敏感字符串，包括短值和嵌套结构。 |
| 数据库并发 | 迁移版本检查与 DDL 共用写锁；首次 WAL 模式切换遇到锁竞争时有限重试。新增 8 连接同步启动回归测试。 |
| 只读回顾 | 没有本轮文件变更或可信测试通过时，回顾文本中的决策/架构表述不会升级为记忆，只保留 Evidence/L0。 |

这些规则主要针对交互任务。最终审查把只读决策/架构提取门槛限定在 `repository-outcome` 策略，保留显式 commit 的原有提取行为，并加入回归测试。显式 commit 与 Host-run 的生命周期策略没有统一改写。本次存储修复不需要新增 schema，也不追溯改写已有敏感数据。

## 架构评估与后续优先级

1. **补足真实效果证据。** 固定一组实际仓库任务，对比有无记忆时的成功率、重复读文件、重复失败命令、耗时及 token 成本。现有严格离线评测主要测上下文质量，不能替代 Agent 实际完成任务的验证。
2. **把向量同步移出检索关键路径。** `VectorIndex.search()` 每次调用 `sync()`，扫描记忆和缓存元数据，再计算候选向量距离。内容哈希能避免重复 embedding，但不能消除全量扫描和同步延迟。后续优先做增量同步，并在当前版本上复测万条记忆规模。
3. **逐步拆分 Core。** 当前 `src/core.ts` 集中承担 Session、提交、检索与治理；提取职责时保持 CLI/MCP 公共契约及事务边界，避免一次性重写。
4. **补集成边界的错误路径覆盖。** 核心存储与治理测试较充分，但服务管理及 MCP 参数/异常分支的覆盖仍相对薄弱。CLI 的子进程测试也不能直接用主进程覆盖率读数衡量；应结合行为测试评估。
5. **明确语义失效与审计边界。** 文件指纹检测无法识别仅在文字中撤回的结论；本次离线报告仍明确显示这一弱项。召回审计记录 `stage: generated`，证明生成了什么文本，不证明宿主成功送达或模型实际使用。Shell 识别同样是保守的常见命令识别，不是完整 Shell 解释器。

此外，L0 活动与召回快照会随物理备份保存，但不属于既有逻辑导出的范围；hooks-only 默认路径降低了对可选 MemoryProxy 服务的依赖。后续产品文档与验收应继续保持这些边界清晰。
