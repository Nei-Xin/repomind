## 无模型验证

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| A01 | 旧 CLI/MCP/core 输入，无 handoff | 原结果、正文、标题和请求幂等行为不变 |
| A02 | 合法单段约束与剩余工作 | 接受；标题使用首条全文；正文逐字保留；Evidence 原文不变 |
| A03 | 中文、emoji、CRLF、组合 Unicode | 精确匹配；code-point 长度和 UTF-16 偏移分别计算；不偷偷 normalize |
| A04 | 同段 Warning/Only/Unless + 约束 | 只能引用整段；不得删除限定语后提取短标题 |
| A05 | 前置独立警告、后置限制、多行代码或列表 | 完整正文仍存在；结构接受不证明语义完整；人工检查所有限定条件 |
| A06 | 首条过长、多行或非完整句 | 不截断、不跳到第二条；采用既有标题回退，报告 titleSource |

| A10 | 超条数、单项/总长度、空白项 | 边界明确且失败原子；不截断成可接受的标注 |

| A12 | 相同 key/相同请求、同 key/不同 handoff、旧 receipt | 分别为原 receipt、冲突、旧 receipt；均不重复写入或迁移 |

## 真实 OpenCode 验收设计

实施后在 `/Users/arkie/Documents/data/test-repomind-test` 新建独立目录，记录设计、
模型和 OpenCode 版本、runtime/提示词/fixtures 哈希。不得复用上一轮结果当作
本协议的验证；阶段 2 只运行无模型回归，不启动模型。

第一道门是**协议可靠性**。选择两个未参与协议样例编写的任务，各两次真实交接。
不在这里预先写入任务答案或固定自然语言标题；只告知字段协议。每次人工检查
constraints 和 remainingWork 对原始任务合同的完整性，特别是条件与负例。
验收要求 4/4 协议被接受且没有实质信息损失、伪造验证或状态提升；失败样本保留，
不靠重复运行凑通过。未达标先报告原因，不宣布泛化成功或继续效率实验。

第二道门是**消费者行为**。对每份真实交接只运行一次 producer：将同一 prose 和
文件变更分别通过自由文本路径及结构化路径回放，两个独立数据库、相同无父提交
代码树、相同命令证据和预算、交替执行顺序，再运行旧/新消费者。共 4 个 producer
和 8 个 consumer（12 个真实阶段）；零模型回放必须单列。

自由文本 arm 不带协议标注，但 prose 必须与新 arm 一致；这是“给定同一份交接时，
结构如何影响存储/消费”的实验，不是与上一轮自然 producer 的端到端对比。由于
新协议会改变 producer 的输出风格、增加输入/输出开销，应单独报告每份 producer
成本。若要声称端到端更省 token，必须另立 producer 协议开/关实验，不混算两种问题。

4 对消费者均要求公开和独立隐藏检查通过；注入需完整、Evidence 来源一致、实际
内容差异明确。另列标题采用率、标题是否表达具体约束（人工标注）、全文注入率和
格式回退率。零标题采用或零注入变化时，不能用消费者 token 波动证明结构化收益。
统计所有 attempts、失败命令、文件读取和耗时；失败配对保留但不进入效率均值。

4 个交接只是功能接入的门槛，不代表总体可靠率或统计显著性。默认开启、正文重排
和其他 adapter 接入属于后续决策，不能仅凭这批小样本自动推进。
