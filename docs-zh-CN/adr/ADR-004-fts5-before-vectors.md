# ADR-004：先使用 FTS5，向量检索后置

状态：accepted

实现说明：先发布作为前置条件的对比基准；随后在 schema v7 中加入 sqlite-vec 混合检索。FTS5 仍是零配置路径和强制回退方案。

## 背景

向量搜索会引入嵌入提供方依赖、缓存管理和模型版本控制问题。大多数仓库查询（命令、文件路径、标识符、错误字符串）都很适合词法匹配。

## 决策

先交付具备标识符感知分词（camelCase/snake_case/路径拆分）和子字符串回退的 FTS5。只有在检索基准就绪、能够衡量收益之后，才加入 sqlite-vec 混合检索。

## 后果

- 搜索可在零配置、离线环境下工作。
- `repomind eval` 提供混合排序必须超越的基线。
- 嵌入失败时回退到 FTS5，不会破坏 Session commit。
